# BankPulse Data Dictionary

This document details the schema, data types, nullability, and descriptions for all tables across the Bronze, Silver, and Gold layers of the BankPulse Lakehouse.

---

## 1. Metadata Schema (`meta`)

### `meta.pipeline_config`
| Column Name | Data Type | Nullable | Description |
|---|---|---|---|
| `config_id` | INT (Identity) | No | Unique configuration surrogate key |
| `entity_name` | VARCHAR(100) | No | Table or entity name (e.g. `customers`, `transactions`) |
| `source_system` | VARCHAR(50) | No | Originating system (`CORE_BANKING`, `CARDS_FILE`, `UPI_FILE`, `KYC_FILE`) |
| `source_type` | VARCHAR(20) | No | Source data format (`SQL` or `CSV`) |
| `source_schema` | VARCHAR(50) | Yes | Source database schema (e.g. `src`) |
| `source_object` | VARCHAR(100) | Yes | Source database table name |
| `source_path` | VARCHAR(300) | Yes | Landing container file path pattern |
| `load_type` | VARCHAR(20) | No | Ingestion mode: `FULL` or `INCREMENTAL` |
| `watermark_column` | VARCHAR(100) | Yes | High-watermark column for incremental filtering |
| `last_watermark` | DATETIME2 | Yes | Watermark timestamp from the last successful execution |
| `watermark_overlap_minutes` | INT | No | Lookback buffer in minutes to absorb late-arriving records |
| `primary_keys` | VARCHAR(200) | No | Comma-delimited business primary keys |
| `pii_columns` | VARCHAR(500) | Yes | Comma-delimited list of sensitive PII columns |
| `pii_method` | VARCHAR(500) | Yes | Masking or hashing strategy mapping per column |
| `dq_ruleset` | VARCHAR(100) | Yes | Associated rule identifier in `meta.dq_rules` |
| `silver_scd_type` | TINYINT | No | Target SCD strategy in Silver/Gold (1 or 2) |
| `load_order` | INT | No | Execution sequence (lower numbers execute first) |
| `is_active` | BIT | No | Active flag (1 = Enabled, 0 = Disabled) |

---

## 2. Silver Layer Entities

All Silver tables inherit business columns with trimmed formatting, plus system audit columns:
- `_silver_ts` (TIMESTAMP): Time of Silver transformation
- `_dq_status` (STRING): Validation outcome (`PASS` or `WARN`)
- `_row_hash` (STRING): SHA-256 fingerprint for change detection

### `silver.customers`
| Column Name | Data Type | PII Masking | Description |
|---|---|---|---|
| `customer_id` | STRING | None | Unique customer business identifier (PK) |
| `full_name` | STRING | MASK | First character + Redacted label |
| `pan` | STRING | HASH | Salted SHA-256 hash of Indian Permanent Account Number |
| `phone` | STRING | MASK | 10-digit mobile number masked as `XXXXXX1234` |
| `email` | STRING | MASK | Email address masked as `u***@domain.com` |
| `address` | STRING | MASK | Redacted street address |
| `city` | STRING | None | City name |
| `state` | STRING | None | State name |
| `pincode` | STRING | None | Postal PIN code |
| `dob` | DATE | None | Date of birth |
| `customer_segment` | STRING | None | Customer classification (`RETAIL`, `HNI`, `CORPORATE`, `SME`) |
| `kyc_status` | STRING | None | Status (`VERIFIED`, `PENDING`, `REJECTED`) |
| `annual_income` | DECIMAL(14,2) | None | Declared annual income |

## 3. Gold Layer Star Schema

### `gold.dim_customer` (SCD Type 2)
| Column Name | Data Type | Constraint | Description |
|---|---|---|---|
| `customer_sk` | BIGINT | PK | Surrogate key generated by window ordering |
| `customer_id` | VARCHAR(20) | FK | Business customer identifier |
| `customer_segment` | VARCHAR(30) | | Customer tier |
| `city` | VARCHAR(50) | | Residential city |
| `state` | VARCHAR(50) | | Residential state |
| `kyc_status` | VARCHAR(20) | | Verification status |
| `age_band` | VARCHAR(20) | | Age segment (`<25`, `25-35`, `36-50`, `50+`) |
| `masked_phone` | VARCHAR(20) | | Masked mobile number |
| `masked_email` | VARCHAR(120) | | Masked email address |
| `hashed_pan` | VARCHAR(64) | | Cryptographic hash of PAN |
| `annual_income` | DECIMAL(14,2) | | Annual income |
| `valid_from` | DATETIME2 | | Start of record validity |
| `valid_to` | DATETIME2 | | End of record validity (NULL if current) |
| `is_current` | BIT | | Active record indicator (1 = Current, 0 = Historical) |

### `gold.fact_transactions`
| Column Name | Data Type | Constraint | Description |
|---|---|---|---|
| `txn_sk` | BIGINT | PK | Surrogate transaction key |
| `txn_id` | VARCHAR(50) | | Business transaction ID across Core, Card, and UPI |
| `date_sk` | INT | FK | Foreign key to `gold.dim_date` (`YYYYMMDD`) |
| `txn_ts` | DATETIME2 | | Original timestamp of payment |
| `channel` | VARCHAR(20) | | Payment channel (`CORE`, `CARD`, `UPI`) |
| `txn_type` | VARCHAR(10) | | Transaction nature (`DEBIT`, `CREDIT`) |
| `txn_mode` | VARCHAR(20) | | Transfer protocol (`NEFT`, `RTGS`, `IMPS`, `POS`, `P2M`) |
| `customer_id` | VARCHAR(20) | FK | Customer identifier |
| `account_id` | VARCHAR(20) | FK | Source account ID (for core transactions) |
| `merchant_id` | VARCHAR(20) | FK | Target merchant ID (for card/POS transactions) |
| `amount` | DECIMAL(14,2) | | Gross payment amount in INR |
| `fee_amount` | DECIMAL(10,2) | | Merchant discount rate or transaction fee |
| `is_debit` | BIT | | 1 if account debit, 0 if credit |
| `status` | VARCHAR(20) | | Settlement outcome (`SUCCESS`, `FAILED`) |
| `fraud_flag` | BIT | | 1 if flagged by risk rules, 0 otherwise |
| `fraud_reason` | VARCHAR(100) | | Explanation of trigger (e.g. `Odd hours + High value spike`) |
| `risk_score` | DECIMAL(5,2) | | Calculated heuristic risk score (0.0 to 1.0) |
| `batch_id` | VARCHAR(50) | | Ingestion execution identifier |

### `gold.kpi_npa_metrics`
| Column Name | Data Type | Description |
|---|---|---|
| `snapshot_date` | DATE | Date of calculation |
| `total_loans_count` | BIGINT | Total number of loans in active portfolio |
| `total_advances_amt` | DECIMAL(16,2) | Total gross loan advances disbursed |
| `gross_npa_count` | BIGINT | Number of delinquent accounts with DPD > 90 |
| `gross_npa_amt` | DECIMAL(16,2) | Total principal outstanding on NPA accounts |
| `gross_npa_ratio_pct` | DECIMAL(6,3) | `(Gross NPA / Total Advances) * 100` |
| `total_provisions_amt` | DECIMAL(16,2) | Regulatory credit loss provisions held |
| `net_advances_amt` | DECIMAL(16,2) | `Total Advances - Total Provisions` |
| `net_npa_amt` | DECIMAL(16,2) | `Gross NPA - Total Provisions` |
| `net_npa_ratio_pct` | DECIMAL(6,3) | `(Net NPA / Net Advances) * 100` |
| `provision_coverage_pct` | DECIMAL(6,3) | `(Provisions / Gross NPA) * 100` |
